Consider: access token in memory, refresh token per tab in sessionStorage (or a named session slot), refresh-cookie path/rotation conflicts between tabs, logout of one tab must not log out others, session-hint logic, realtime/SSE per tab, 'remember me on this device' for single-user devices. Optimised for speed and zero confusion under pressure. Keep the dark theme + design system (ADR-031).

6. **Dialog/card closes when a text selection drag ends outside.** Selecting text inside a card/dialog and releasing the mouse outside closes it — wrong. ### QR menu API contract (Q-API agent implements; Q-WEB + Q-STAFF consume; amend this section if reality differs and tell the others in your report — keep it current)
Public (no auth, rate-limited, prefix as existing API prefix; web calls `${API_BASE}/public/menu/...`):
- `GET  /public/menu/:tableToken` -> 200 { business:{name,slug,tagline?,logoUrl?,coverUrl?,accentColor,currency:'INR'}, table:{label,areaName?,open:boolean}, settings:{ordering:'off'|'confirm'|'auto', callWaiter:boolean, payment:{upi:boolean}}, categories:[{id,name,description?,imageUrl?}], items:[{id,categoryId,name,description?,priceMinor,imageUrl?,blurDataUri?,veg?:'veg'|'nonveg'|'egg',tags:string[],spice?:0-3,soldOut:boolean,variants:[{id,name,priceMinor}],addOnGroups:[{id,name,min,max,options:[{id,name,priceMinor}]}]}], etag, serverTime }  (supports If-None-Match -> 304)
- `GET  /public/menu/:tableToken/stream` (SSE) events: menu.changed {etag}, table.updated {open}, order.updated {orderId,status,...}, bill.updated {...}, waiter.ack
- `POST /public/menu/:tableToken/guest` -> {guestToken, expiresAt} (device guest identity; optional {displayName})
- `POST /public/menu/:tableToken/orders` (header X-Guest-Token, Idempotency-Key) { lines:[{itemId,variantId?,addOnOptionIds?:string[],qty,note?}], note? } -> 201 { orderId, status:'AWAITING_CONFIRMATION'|'CONFIRMED', totalMinor }
- `GET  /public/menu/:tableToken/state` (X-Guest-Token) -> { orders:[{id,status,lines,placedAt,timeline:[...]}], bill:{subtotalMinor,taxLines:[...],totalMinor,paidMinor,dueMinor,status}, waiterCall:{open:boolean} }
- `POST /public/menu/:tableToken/waiter` { reason:'call'|'bill'|'water'|'other' } -> 202 ;  `POST /public/menu/:tableToken/pay-intent` { method:'upi' } -> { upiUri, qrPayload, amountMinor, reference } (staff still confirm receipt)
Staff (existing auth/permissions; new permissions `restaurant.qr.manage`, `restaurant.guestorder.manage`): `GET/POST/PATCH /admin/qr/tables` (list tokens, rotate, enable), `GET/PATCH /admin/qr/settings`, `POST /admin/menu/items/:id/image` (+DELETE), `GET /admin/guest-orders?status=` , `POST /admin/guest-orders/:id/confirm|reject|edit`.
Money = integer minor units (paise). Terminology per CANONICAL_GLOSSARY (Service Request = the order; Guest Session; Checkout; KOS). Guest orders are Service Requests with source=GUEST.

### QR menu API contract: AS IMPLEMENTED (Q-API, 2026-10-31; supersedes the sketch above where they differ; ADR-035, reports/11_QAPI_REPORT.md)
Everything above holds; these are the exact additions and differences. Errors are `{ error: { code, message, details? } }`; 429 carries `Retry-After`.
- **Ids.** A guest order's id is the Service Request id everywhere: `orderId` returned by `POST .../orders`, `orders[].id` in `/state`, `id` in `GET /admin/guest-orders` and the `:id` of `confirm|reject|edit`. (`guestOrderId` is also returned to staff, informational.)
- **Headers.** `POST .../orders` REQUIRES `Idempotency-Key` (8-100 chars `A-Za-z0-9_-`) and `X-Guest-Token`; a replay returns 200 + `Idempotent-Replay: true`, the same key with a different body 409 `IDEMPOTENCY_KEY_REUSED`. Staff `confirm|reject` are naturally idempotent; `edit` honours `Idempotency-Key`.
- **Menu** `GET /public/menu/:t`: as sketched; `veg` is `'veg'|'nonveg'|'egg'` (from `MenuDietType`), `variants[].priceMinor` and `addOnGroups[].options[].priceMinor` are ABSOLUTE (variants) / add-on prices (options); unavailable variants/options are omitted; `soldOut` when the item is off or all variants are off. `imageUrl`s are absolute. ETag is weak (`W/"..."`), `etag` in the body equals the header, `Cache-Control: private, no-cache`; a closed table is still 200 with `table.open=false`. 404 unknown/malformed token (identical body), 403 `MENU_DISABLED` (restaurant switch, table switch, inactive business or module).
- **Guest** `POST .../guest` (body `{displayName?}`, strict) -> 201 `{guestToken(43 chars, 256-bit), expiresAt}`; 409 `TABLE_CLOSED` when no visit is open. The token is bound to table + the OPEN visit: when the visit closes (or the QR is rotated) it stops working (401 `GUEST_TOKEN_INVALID`; the client re-issues).
- **Order errors.** 403 `ORDERING_OFF`, 409 `TABLE_CLOSED`, 409 `SOLD_OUT` (item, variant or add-on), 400 `VARIANT_REQUIRED` / `ITEM_NOT_ON_MENU` (`details.reason`), 409 `ORDERING_LOCKED` once a bill (invoice) exists for the visit, 429 `RATE_LIMITED` (also `details.reason: PENDING_ORDERS` when >5 guest orders wait for the waiter). Caps (env-tunable): 25 lines, qty 20 per line, 60 items per order.
- **State** `GET .../state` (X-Guest-Token): `orders[]` = the guest's own orders + every confirmed order of the table; other guests' pending/rejected orders are never shown. Order: `{id,status,mine,edited,placedAt,note,totalMinor,rejectReason?,lines:[{itemId,name,qty,variantName,addOns:string[],note,lineTotalMinor}],timeline:[{status,at}]}`; status vocabulary `AWAITING_CONFIRMATION|CONFIRMED|PREPARING|READY|SERVED|REJECTED|CANCELLED`. `bill` is `null` until something is confirmed, then `{subtotalMinor,taxLines:[{name,label,ratePercent,amountMinor}] (GST shown as CGST + SGST halves),totalMinor,paidMinor,dueMinor,status:'RUNNING'|'FINAL'|'PAID',reference|null}`; RUNNING = live total that equals the invoice the cashier will generate. `waiterCall` = `{open:false}` or `{open:true,reason,at}`. With no open visit: `{orders:[],bill:null,waiterCall:{open:false}}`.
- **Waiter** `POST .../waiter` -> 202 `{open:true,reason,at}`; one OPEN call per table+reason (pressing twice = the same call); X-Guest-Token optional; 403 `ORDERING_OFF` code when the restaurant switched calls off.
- **Pay** `POST .../pay-intent` `{method:'upi'}` -> 200 `{upiUri,qrPayload(=upiUri),amountMinor(amount still due),reference}`; 409 `UPI_UNAVAILABLE` (not enabled or no UPI ID in Checkout settings) / `BILL_NOT_READY` (no finalised bill, or nothing due). Staff still record the payment.
- **Stream** `GET .../stream` (EventSource, no headers possible, so it carries HINTS only: ids and statuses, never names/items/amounts): `hello {serverTime,heartbeatSeconds}`, `menu.changed {etag}`, `table.updated {open}`, `order.updated {orderId,status}`, `bill.updated {}`, `waiter.call {}` (a waiter call opened), `waiter.ack {}`, `bye {reason}` (then the server closes; reasons `refresh` after 30 min, `token-changed`, `unavailable`). On any event the page re-reads `/state` (or the menu) with its guest token. Comments `: ping` every 20 s. 429 `RATE_LIMITED` when too many concurrent streams per IP (20) or table token (60).
- **Staff QR** `GET /admin/qr/tables` -> `[{tableId,code,areaName,locationId,token,path:'/m/<token>',url|null,enabled,orderingEnabled,rotatedAt,rotationCount,version,pendingGuestOrders,waiterCall:{open,reason,at}|null}]` (creates missing tokens on first call). `POST /admin/qr/tables/:tableId/rotate` (200, body `{expectedVersion?}`; old link 404 at once, guest tokens revoked, open streams end), `PATCH /admin/qr/tables/:tableId` `{enabled?,orderingEnabled?,expectedVersion?}`. `GET|PATCH /admin/qr/settings` `{enabled,ordering:'off'|'confirm'|'auto',callWaiter,upi,tagline,accentColor,logoUrl,coverUrl,version}` (PATCH accepts `expectedVersion`). `POST|DELETE /admin/qr/settings/logo|cover` (multipart `file`, optional `blur`, `color`).
- **Photos** `POST /admin/menu/items/:id/image` (multipart field `file`; png/jpeg/webp by magic bytes, 64..6000 px, <=24 MP, no animation, <=6 MiB; metadata stripped; content-addressed) -> 200 `{itemId,imageUrl:'/media/<businessId>/<sha1>.<ext>',imageThumbUrl,blurDataUri,color}`; `DELETE` -> 204 (idempotent). Same for `/admin/menu/categories/:id/image`. `PATCH /admin/menu/items/:id/presentation` `{dietType:'VEG'|'NONVEG'|'EGG'|null, menuTags:string[<=6], spiceLevel:0-3|null}` (not in the original sketch; the staff catalog editor does not call it yet). `GET /admin/catalog/items` now carries `imageUrl`, `dietType`, `menuTags`, `spiceLevel`. Pictures are served by `GET /media/:businessId/:file` (public, `immutable`, ETag/304). With `sharp` installed they are re-encoded to WebP (+480 px thumb, blur data URI, dominant colour); without it the original is kept (metadata stripped, thumb null).
- **Guest orders (staff)** `GET /admin/guest-orders?status=AWAITING_CONFIRMATION|CONFIRMED|REJECTED|CANCELLED&locationId=&take=` (default: last 24 h) -> rows `{id,guestOrderId,requestNumber,status,requestStatus,decision,mode,source:'GUEST',tableId,tableCode,areaName,sessionId,locationId,guestName,placedAt,decidedAt,decidedBy,rejectReason,note,version,lines:[{id,name,variantName,qty,unitPriceMinor,addOns:[{name,priceMinor}],note,cancelled}],totalMinor}`. `POST /admin/guest-orders/:id/confirm` (-> numbered SENT request, kitchen sees it), `/reject` `{reason}`, `/edit` `{lines:[{id,qty(0 removes)}],note?}` (only while awaiting confirmation; 409 `NOT_AWAITING_CONFIRMATION` after). All return the row. `GET /admin/guest-orders/alerts` -> `[{id,tableId,tableCode,areaName,locationId,reason,at}]`; `POST /admin/guest-orders/alerts/:tableId/ack` -> 204.
- **Permissions.** `restaurant.qr.manage` (owner/wildcard, location-manager) for `/admin/qr/*` and `/admin/menu/*`; `restaurant.guestorder.manage` (owner, location-manager, service-team = waiter) for `/admin/guest-orders/*`. Existing databases need `prisma db seed` to refresh system roles.
